Test strategy

I start from what would hurt if it broke, and put the cheapest reliable check in front of it. A rule that can be code is code; a judgment that needs a model gets an eval gate with an answer key. Tests run offline and do not depend on today's date, so a red build means a real problem.

Design decisions

Each one names what I rejected and why. ReqTrace keeps a full decision log.

Take the Wheel: a browser agent

  • The security boundary is a deterministic hook, not the tool allowlist. Claude Code auto-approves read-only commands before it checks --allowedTools, and a wildcard rule let through the user's GitHub CLI and file uploads. guard.mjs runs before every command and fails closed.
  • Safety lives in code because the model is not consistent. In testing, Haiku tried the forbidden commands, and Opus sometimes refused even an authorized test. A check that depends on the model behaving is not a check.
  • Submitting a form is locked in code. The final submit is refused unless the user's own task asks for it.
  • Each run starts in an empty sandbox with no connectors or skills, so no stray instructions leak in and every turn costs less.

ReqTrace: AI for regulated engineering

  • Anything that can be a rule is a rule. The model gets a closed four-type taxonomy enforced by the schema, and deterministic checks handle traceability.
  • Reused test steps are copied verbatim, never paraphrased by the model. In a controlled document, a paraphrase is an unapproved change.
  • The citation guardrail drops and counts, never repairs. A finding that cites an unknown requirement is removed and reported, not quietly fixed.
  • A cheaper model earns a step only by passing the same gate. Three of four local-model routings failed and were rejected or redesigned. The one that passed cut model cost 55%.
  • Reproducibility comes from recorded fixtures, because temperature 0 is not available. The fixture key includes the prompt, so a prompt change cannot replay a stale answer.

Market Terminal: a data pipeline

  • Missing is not zero. A failed source is shown as missing, with the reason. No fallback constants, no carried-forward prices.
  • One immutable snapshot per run; renderers never fetch. Database triggers block updates and deletes of snapshots.
  • Every network call goes through one gate that bounds, deduplicates, logs and stores it, and makes no calls in offline runs.
  • Known trade-offs are written down in known issues, not hidden.

Working with coding agents

I use Claude Code and other agents to build faster, and I treat their output the way I treat any system under test: it has to prove itself. The root causes above are what that looks like in practice.

  • One rulebook, enforced by CI. Market Terminal's AGENTS.md sets ten hard rules for every agent: never send or publish anything, missing is not zero, tests stay offline. The rules a machine can check are checked in CI, so an agent that breaks one fails the build.
  • Verify, don't accept. I re-run the tests and the linter myself after delegated work, and the decision log records it.
  • Humans approve. Every ReqTrace output is stamped Draft, requires engineer review. Not for execution.
  • Cost is measured, not guessed. Every eval run lands in a ledger with its model, cost and result.
